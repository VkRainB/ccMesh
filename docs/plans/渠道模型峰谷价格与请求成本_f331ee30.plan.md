# ccMesh：渠道 × 实际出站模型的每周峰谷价格、报价查询与请求成本

对照 cc-switch 的四项模型价及 LiteLLM 的时段价格覆盖。只改 ccMesh 的端点配置、[forward.rs](src-tauri/src/modules/proxy/forward.rs)、[aggregator.rs](src-tauri/src/modules/stats/aggregator.rs) 和关联存储、查询与界面；新增统一价格解析模块。Pi/OMP 外部工具配置的兄弟实现、本机 `usage_records` 和 Cursor 官方账单保持原样。源仓库 `F:/IT/cc-switch` 全程只读，不搬迁整个计费系统。

## 1. 渠道模型价格配置

### 核对结果与已确认范围

- 已确认：同时落实价格管理、渠道模型报价查询和代理请求成本统计；采用每周重复时段，不做指定日期例外或自动节假日规则。代码及验收已完成；本节源代码行号和「拟新增」说明记录实施前的研究基线，最终界面以第 4 节及抽屉计划为准。
- cc-switch：`src-tauri/src/services/model_pricing.rs:33-40` 的 `ModelPricingInfo` 有输入、输出、缓存读、缓存创建四价；`database/schema.rs:244-254` 的价格主键仅为 `model_id`。`schema.rs:2409-2427` 明确说明无时段维度、统一录高峰价，不能直接复用为渠道峰谷价。
- cc-switch：`src/lib/modelMetadata.ts:349-409` 按同地址预设、models.dev 同供应商、原厂元数据补全；原厂兜底不携带转售渠道价格。`src/lib/modelsDevPricing.ts:207-221` 导入按归一化模型 ID 去重，会丢失供应商维度。自动同步与手工更新走同一写入接口，不具备手工价保护层。
- cc-switch：`services/model_fetch.rs:13-62` 只查模型目录；`services/balance.rs` 查询余额。`proxy/usage/logger.rs:350-361,406-440` 按模型查价并固定倍率 1；历史回填仍可能使用历史倍率。三条链路不能合并解释为“渠道实时结算价”。
- ccMesh：`commands/models.rs:85-103` 只返回模型 ID；`models_cache.rs:20-28` 的 `endpoint_id` 实际承载端点名，不能用于价格主键。`piConfig.ts:41-47` 的 `inputTokensAbove` 是 token 阶梯，不是时间规则。
- ccMesh：`models/stats.rs:66-96` 无金额；`aggregator.rs:128-129` 以完成时刻记录日志；`forward.rs:135-151` 无稳定端点 ID 的计价上下文。仅增加表单不会让统计产生费用。

### 存储与字段（以下是拟新增契约，不是现有字段）

沿用端点 JSON 列惯例，在 `migration.rs:195` 后追加迁移，给 `endpoints` 增加 `model_pricing` JSON 文本列，缺省 `[]`；不新建全局模型单价表。`Endpoint`、`CreateEndpointRequest`、`UpdateEndpointRequest` 和前端对应类型增加 `modelPricing`；修改 `endpoint_repo` 的列、解码、创建、更新与校验。

- 每个价格项包含 `modelId`、`timezone`、`baseRates`、`windows`。渠道身份是所属 `Endpoint.id`，模型使用实际出站 ID 精确匹配，不去 namespace、不按前缀猜价，不按 API URL 合并。
- `baseRates` 四项使用现有概念 `input/output/cacheRead/cacheWrite`，值为非负十进制字符串，单位固定为 USD / 百万 token，与现有 Pi/OMP 价格单位一致；不是自动汇率换算。四项必须完整，可显式为零；缺少价格项才是未配置。
- 每个时段包含 `id`、`name`、`weekdays`（ISO 1–7）、`startMinute`、`endMinute`、`rates`（完整四价）。所有时段共用该模型价格项的 IANA `timezone`，默认 `Asia/Shanghai`，不跟随操作系统时区。
- 时间精度为分钟，区间左闭右开。跨午夜的星期归属于开始日，例如周五 22:00–次日 08:00 包含周六凌晨。结束允许 1440 表达当日 24:00；开始与结束相等拒绝，全天使用 00:00–24:00，避免零长度歧义。
- 同一渠道模型内不允许重叠时段；按周展开并检查跨周重叠。未命中任何时段使用默认价；峰、谷只是名称，支持多个价档，不限制必须谷价更低。
- 保存时拒绝重复模型 ID、非法时区、空星期、超范围分钟、负数、非有限值及不支持精度；文案为「该模型存在重叠的价格时段」「请选择有效时区」「价格必须是非负十进制数」。损坏的持久化配置不能静默解释为免费。
- `clone_endpoint`（`commands/endpoint.rs:99-123`）复制完整规则但使用新端点 ID，后续互不影响。删除端点删除其配置，不删除历史快照；归档、改名不改变价格身份。`cc_switch_migration/importer.rs:121-138` 新字段初始化为空，不把源仓库全局价误当渠道合同价。

## 2. 时段解析与渠道报价查询

新增 `src-tauri/src/modules/pricing.rs`，只承担规则校验、选价与四桶金额计算；前端不写第二份时间匹配器。新增 `src-tauri/src/models/pricing.rs` 定义上述 DTO 及费率快照。金额使用 `rust_decimal`，时区使用 `chrono-tz`；现有 `chrono` 不提供任意 IANA 时区数据库，现有依赖也没有十进制金额类型，因此增加这两个直接依赖而不手写替代品。

- 拟新增纯函数 `resolve_price(endpoint, outbound_model, at_utc)`；先精确定位渠道模型，再将同一 UTC 时刻转换到规则时区并匹配星期、分钟。DST 回拨重复小时两次均按同一墙钟规则，跳过的小时自然没有请求时刻。
- 选定“时段完整四价覆盖默认四价”，不做总额倍率，也不组合 Pi 的 token 阶梯。它能表达输入、输出与缓存折扣不同的渠道政策。
- 拟新增 `commands/pricing.rs` 的 `get_endpoint_model_prices`，接收端点 ID、可选 UTC 毫秒预览时间，返回模型 ID、默认价、当前有效四价、命中时段、时区、报价时刻及下次变化时刻；缺价显式返回未配置。查询不修改配置，不产生费用记录。
- 查询和实际计价复用同一解析器；前端通过新 `src/services/modules/pricing.ts` 调用。新增命令、模型及模块在现有 `commands/mod.rs`、`models/mod.rs`、`modules/mod.rs` 与 `lib.rs` 注册。
- 渠道价由用户维护；models.dev 和原厂价属于参考来源，本阶段不自动抓网页、不自动同步覆盖自定义价、不新增所有供应商的报价适配器。现有 `/models` 仍只负责模型候选。不能因缺价而套用另一个渠道同名模型的价格。

### GitHub 已有设计与采用边界

- [LiteLLM #31725](https://github.com/BerriAI/litellm/pull/31725) 已于 2026-09-01 合入其 `litellm_internal_staging`：`off_peak_pricing` 支持多个 UTC 窗口、星期、星期日历时区、跨午夜、部署级隔离。已读 [实际 diff](https://github.com/BerriAI/litellm/pull/31725.diff)，不是仅依据 issue 标题判断已实现。
- 其 `_apply_off_peak_pricing` 在选完普通/阶梯价后覆盖输入、输出、缓存读；缓存创建仍用原价。ccMesh 借鉴统一入口和渠道隔离，不照搬其“缺项回退”、等起止代表全天及非法时区回退 UTC；本计划使用完整四价并在保存时拒绝错误。
- [LiteLLM #31606](https://github.com/BerriAI/litellm/issues/31606) 的讨论指出星期时区、历史生效日期及渠道不同窗口的风险；讨论建议不等于 PR 已实现全部能力。本计划通过请求快照防止改价重算历史，不承诺历史费率版本回查。
- [New API #7010](https://github.com/QuantumNous/new-api/issues/7010) 是已关闭的峰谷价请求，但页面没有关联实现 PR，不能据此认定其当前版本已支持完整设计。
- [DeepSeek 官方价目](https://api-docs.deepseek.com/quick_start/pricing) 当前有峰谷及中国法定节假日例外。本计划按用户选择只做周规则，不能完整复刻其节假日结算；按用户最终要求不在界面重复展示这段说明。不硬编码易过期的官方价目。

## 3. 请求费率快照与成本统计

在 `forward.rs:743` 调用 `send_upstream` 前，记录该次上游尝试的 UTC 开始时间，使用已选端点和完整 `outbound_model` 解析价格并冻结快照。不要等 `:777` 收到响应再取当前时钟；现有 `started_ms` 继续负责整次入站请求耗时。

```mermaid
flowchart LR
  A[选定端点与出站模型] --> B[上游尝试开始时冻结四价]
  B --> C[沿用响应与流式 usage 解析]
  C --> D[统一 RequestRecord 计算估算成本]
  D --> E[同事务写请求快照及日聚合]
```

- `RequestMeta`、`RequestRecord`、`RequestLog` 拟增加 `endpoint_id`、`pricing_model`、`pricing_at`、`pricing_snapshot`、`cost_status`、四项成本和总成本。快照包括默认/时段来源、规则 ID/名称、时区及四项有效单价，不含凭据；实际出站模型即使与入站大小写相近也单独完整记录，不能依赖展示用 `actual_model`。
- 沿用 `modules/usage.rs:20-22` 的非缓存净输入语义，成本为四桶 token 各乘对应单价再除一百万；不再次扣缓存。单价限制到小数点后 9 位；用 checked Decimal 运算，每项按 12 位 USD 小数四舍五入，总额为四个已舍入分项之和。溢出标记计算失败，不能变成零或让代理请求失败。
- 扩展 `TokenUsage` 的完整性信息，区分上游明确报告零 token 与字段缺失；覆盖 `from_response`、`UsageAccumulator.feed_json/finish` 及 `forward.rs` 的转换后用量构造。保留 `output_estimated` 现有行为，不改 token 统计口径。
- 拟定成本状态为 `priced/unpriced/incomplete_usage/calculation_error/legacy_unknown`。完整 usage 与四价才能进入 `priced`；显式免费仍是 `priced` 且金额零。字符估算、断流缺最终 usage、缺价及旧记录不显示成免费，金额为空并记录原因。错误状态但有完整 usage 时仍计价，不按 HTTP 错误一律归零。
- 流式、非流式与协议转换都通过统一记录入口计价；`forward.rs:962-977` 的全端点失败兜底也补齐状态。切换渠道的每次尝试重新冻结价格，只给已有记录且有完整 usage 的尝试计费，不把不可观测的上游失败费用算作已知零，不声称本地汇总等于供应商完整账单。
- 给 `request_logs` 追加快照和金额列，旧记录标为 `legacy_unknown`，不按当前价回填。删除/改价、改名后历史记录仍展示原快照；不创建无证据的历史渠道映射。
- `daily_stats` 增加已计价金额、已计价请求数、未计价请求数，旧行的既有请求全部作为未计价；沿用当前端点名、完成日、设备的聚合口径，与现有 token 报表一致，稳定端点 ID 用于选价及请求明细，不暗改历史分组。汇总明确是「已计价部分」；按用户追加要求不展示覆盖率或已计价/未计价数量，内部计数仍用于区分免费与未知金额。跨天请求价格按尝试开始、统计仍按完成日归属。
- 金额在 SQLite 用十进制 TEXT、API 用字符串，不能对 TEXT 用 SQLite 浮点 `SUM`。`stats_repo` 以 Decimal 累计各日金额；`Delta` 在内存累计。`RequestLog` 分页与事件均携带同一结果，小时 token 趋势保持原样。
- `aggregator.rs:187-225` 当前先 drain 再分开写日表和日志；金额加入后必须让同一批日志与日增量在同一事务提交，串行化 flush，提交失败保留原批次供下一次现有刷新处理。`request_logs_repo::insert_batch` 改为参加外层事务，不嵌套提交，避免日费用已累加但请求快照未落库。
- 明细仍保留 90 天，清空明细不删除日金额；删除历史日统计沿用现有行为。`usage_records` 没有可靠渠道身份，不能套用渠道价；Cursor 自带官方金额，不混入该估算账本。

## 4. 价格编辑、报价查询与费用展示

新增 `ModelPricingDialog.tsx`，对照 `ModelMappingDialog.tsx` 的独立编辑态、保存与查询失效机制，在 `EndpointCard.tsx` 的「更多操作」菜单提供「模型价格」。已按用户截图修正：主操作行不显示价格图标，右侧可用模型也不显示价格入口。沿用现有 Dialog、表单和错误提示组件。

- 编辑对象为该端点出站模型，可选择已有模型或手输准确 ID；四项默认价、时区、星期、多时段四价在同一弹窗维护。按钮原文「添加时段」「保存价格」「删除模型价格」；删除确认「删除后，新请求将显示未配置价格；历史估算成本保持不变。」
- 弹窗提供「当前有效价」与指定时间预览，显示输入、输出、缓存读取、缓存创建，单位「USD / 百万 token」。未配置显示「未配置价格」，免费显示「0」，不能把空输入自动转成零。
- `ModelList.tsx` 保持只展示可用模型、搜索与复制，不提供价格图标或报价弹窗。价格查询仍在「更多操作 → 模型价格」弹窗中提供；后端保留入站别名解析后的报价接口。
- 价格界面打开、窗口重新聚焦、`endpoints-changed` 和下次价格变化时刷新；休眠唤醒重新向后端查询。前端定时器只刷新展示，不负责切换真实费率。
- `RequestMonitor.tsx` 在 Token 第二行展示价格或未计价状态，移除独立成本列和详情图标；实时监控与统计请求记录共用。行点击、Enter/Space 或价格打开右侧详情，展示四项估算成本、计价模型、规则、时区和 `pricing_at`。`EndpointStatsTable.tsx` 只增加「已计价成本（USD）」，不展示计价覆盖率，周期数据仍由既有 `get_stats` 返回。
- 按用户最终要求，移除本地估算、渠道账单、每周规则等说明性文案。缺 token 仍显示「用量不完整，未计价」，旧记录仍显示「历史记录无费率快照」，真实零价仍为 `$0`。不增加按价格自动切渠道、延迟请求或余额差额推算。
