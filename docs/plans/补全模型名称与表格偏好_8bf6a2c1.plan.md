# 补全模型名称与表格偏好

## 背景与现状

[`src-tauri/src/modules/models_cache.rs`](src-tauri/src/modules/models_cache.rs):15-22 不含 display_name；[`src-tauri/src/modules/proxy/server.rs`](src-tauri/src/modules/proxy/server.rs):176-231 从配置读取外部列表，不读上游缓存。仅在聚合缓存补字段不能保留外部列表的上游名称。

[`src/components/business/RequestMonitor.tsx`](src/components/business/RequestMonitor.tsx):132-159 固定九列，Dashboard 与统计页共用。用户指定参考 [`docs/plans/useCache.md`](docs/plans/useCache.md) 的单键持久化与同步设计。

## 目标

- display_name 优先上游非空名称，否则模型 ID；外部 OpenAI/Anthropic 两种格式保持模型公布规则。
- 删除按钮旁配置九列可见性，至少保留一列；两处共用且刷新恢复。
- 单一“仅显示实际模型”开关；无实际模型回退请求模型；默认保持原展示。

## 方案

### 1. 模型名称

沿现有模型探测与表单刷新保留名称，复用 app_config 的 modelDisplayNames 索引（API URL → 模型 ID → 名称）。同 URL 的端点和克隆共享上游目录；失败刷新不覆盖历史名称，换 URL 不继承旧来源。配置导出及 WebDAV 白名单纳入索引。旧配置缺失时回退；外部列表继续本地读取，不增加每次请求的上游调用。别名没有同名上游名称时使用别名 ID。

### 2. 请求表格配置

在共享 RequestMonitor 内复用现有 UI 组件增加配置入口。最小 TypeScript useCache 使用原生 localStorage，自定义事件同页同步及 storage 跨标签同步，存储不可用时维持当前会话状态。缓存键 ccmesh:request-table-preferences:v1；只保存 hiddenColumns 与 actualModelOnly。表头与行共用列配置，ModelCell 处理实际模型开关。

### 3. 验证交付

先针对性验证，再更新进度与 changelog，按精确文件分模块提交。

## 风险与注意

配置态没有上游名称的历史端点须再次刷新模型才得到名称，此前用 ID。localStorage 被禁止时无法跨重启持久化，但 UI 不应崩溃。浏览器使用短时转译的真实组件及实际应用 CSS，临时 IPC 只注入请求数据；不启动 build/dev，不声称桌面 WebView 已验证。
