# 端点统计：行内展开实际出站模型的请求数

只改 [aggregator.rs](src-tauri/src/modules/stats/aggregator.rs)、[stats_repo.rs](src-tauri/src/modules/storage/stats_repo.rs)、[EndpointStatsTable.tsx](src/pages/Statistics/_components/EndpointStatsTable.tsx) 及下列相关类型、迁移和调用方。已确认采用端点行内展开、实际出站模型口径、长期保留模型计数；沿用现有端点汇总列、日期选择器和统计事件。兄弟实现中的本机用量、请求详情抽屉、价格计算和代理重试保持原样。

## 1. 持久保存模型请求数

### 已核对的原因

- `migration.rs:33–46` 的 `daily_stats` 按 `endpoint_name + date + device_id` 唯一，没有模型维度；`stats_repo.rs:59–97` 汇总到端点后，也没有模型计数。
- `forward.rs:749–764` 已把本次出站模型存入 `RequestPricing.model_id`，不依赖是否配置价格；`Pending::record` 又将其存为 `request_logs.pricing_model`。无需重新解析代理请求或修改转发流程。
- `actual_model` 仅在映射或锁定改写时记录，旧记录和透传均可能为 NULL，不能把所有 NULL 都判断为请求模型就是出站模型。
- `aggregator.rs:22–32,254–269` 自动清理超过 90 天的明细；`commands/stats.rs:60–65` 支持清空明细但保留日汇总。直接聚合当前明细，不能保证历史模型数量与端点总请求数一致。

### 改动

选定在 `daily_stats` 同一行增加 JSON 计数字段，与端点请求总数共同累计、删除。独立模型表需要额外处理删除和备份清理，本阶段不建；也不从前端当前页请求列表计算。

- 在当前 v21 后追加 v22 迁移，新增 `model_requests TEXT NOT NULL DEFAULT '{}'`。内容为「实际出站模型原文 → 请求数」，不写入展示用的「模型未记录」键，不新增依赖。
- `Delta` 增加 `BTreeMap<String, i64>` 类型的 `model_requests`，移除不再适用的 `Copy` 派生。`Pending::record` 在累计一次端点请求时，同时累计一次已知模型；只在新增模型键时复制模型名。
- 模型取非空 `rec.pricing.model_id`，缺失时取非空 `rec.actual_model`；都没有则不增加已知模型计数。不能用 `rec.model` 猜测出站模型，也不按当前端点配置重新解析历史映射。不去供应商前缀，不合并大小写不同的名称。
- 计数沿用现有请求完成记录：成功、错误、无 usage、未配置价格都计入；一次 `record` 只加一，重试尝试数不另计。日期沿用 `StatsAggregator::record` 的 `periods::today()`，不是选价时的 `pricing_at`。
- 扩展 `stats_repo::upsert` 已有的旧金额读取，同时取出旧模型计数并逐项累加，不能用本批增量覆盖历史。模型计数、日汇总、请求明细仍在 `Pending::commit` 的同一事务内提交；提交失败保留整批，成功后才清空。
- JSON 解码沿用仓库的显式错误处理，不用空对象兜底吞掉坏数据。始终保证已知模型计数之和不大于该行 `requests`。

### 历史回填

只在 v22 迁移事务中执行一次，不能每次启动或每次展开都重新扫请求日志。

- 按现有本地日期口径，从 `request_logs.ts` 推导日期，连同 `endpoint_name`、`device_id` 匹配日汇总；不只按端点名匹配，也不使用开始计价时间。
- 仅当该组现存明细总数与 `daily_stats.requests` 完全一致，才允许回填其中有可信出站模型的记录；模型来源依次为非空 `pricing_model`、非空 `actual_model`。
- 明细数量不一致、日期不能对应或日志已经清理的组，整组保持 `{}`，不按比例分摊、不截断数量凑总数。完整组中模型字段缺失的记录仍保留为未记录差额。
- 不修改原有请求总数、Token、金额或计价状态。迁移再次执行不得重复累加。
- 已只读核对现有隔离数据：截图中 Chat A 的日汇总为 25，按同端点、同设备、同日匹配到的明细也是 25，且均有出站模型；其中 `priced-model` 为 23，另两个模型各为 1。这个核对不是未来功能已实现的证明。

## 2. 汇总与日期筛选

- 在 Rust 的 `DailyStat`、`EndpointStat` 新增 `model_requests: BTreeMap<String, i64>`；在 `src/services/modules/stats.ts` 的对应接口新增必填 `modelRequests: Record<string, number>`。`PeriodStats` 不另加跨端点模型榜单。
- `stats_repo::row_to_daily` 读取新列；`period_stats` 按端点逐项累计模型数量，`history_page` 合并同端点同日的设备行时也逐项累计。查询只读取持久汇总，不依赖 `request_logs`。
- `EndpointStatsPanel.tsx:76–129` 的 `aggregateRange` 在原有日期闭区间过滤和端点合并中同步合并 `modelRequests`，否则今日与自定义范围会出现两套口径。
- 前端累加模型名使用 `Map`，需要对象时使用 `Object.fromEntries`；模型名是外部字符串，不能用普通对象的原型属性作初值。
- 沿用 `get_stats`、`get_stats_history`、`stats-updated` 和 `useStats` 的 `['stats']` 失效机制，不新增 Tauri 命令、事件、轮询或展开时的请求。`commands/stats.rs` 和 `useStats.ts` 调用方不动。
- 沿用现有历史分页及自定义范围取数方式；本阶段不改热力图、小时趋势或历史弹窗展示，也不扩大其取数范围。同步更新受影响的手写统计对象和已有测试输入。

## 3. 端点行内展开

在 `EndpointStatsTable.tsx:29–56` 的端点行下插入可展开子行，主表仍为现有八列，不恢复计价覆盖率列。

- 默认收起。端点名称与左侧小折叠箭头组成原生按钮；点击展开或收起，支持 Enter/Space，设置 `aria-expanded` 和 `aria-controls`。可访问名称为「展开 {端点名} 的模型统计」或「收起 {端点名} 的模型统计」。
- 展开行使用 `colSpan={8}`，内部只显示「模型」「请求」两列；不增加模型 Token、金额、占比、搜索或新抽屉。一次允许展开多个端点。
- 已知模型按请求数降序、同数量按模型名升序展示；请求数显示完整整数。长模型名沿用 CSS 省略并保留完整悬停值，不截断原始字符串。
- 计算 `未记录数量 = 端点 requests - 已知模型计数合计`。大于零时在末尾增加「模型未记录」行；为零时不显示。该行是独立展示项，不能与恰好同名的真实模型合并。
- 每个端点子表的全部请求数之和必须等于父行请求数；只有旧数据或无法确定出站模型时才出现未记录差额。不要把这部分显示为零或隐藏。
- 同一日期范围的统计刷新保留展开状态；在 `EndpointStatsPanel` 给表格提供范围对应的 React `key`，用户切换日期范围时重置展开状态。主表金额、Token 格式、端点名称统计键和原有空态保持原样。
- 不新增解释段落或额外详情图标；本次入口仅用于模型统计展开，不影响请求表格的详情入口。

## 4. 验证模型统计及生命周期

以下为实施后的验收；当前计划的全部实施步骤仍为 pending。

- 在现有 `aggregator.rs`、`stats_repo.rs` 测试中覆盖：同端点多个模型、多个别名指向同一出站模型、同模型跨端点、错误和未计价请求、未知模型差额、两批累计及事务失败后重试不重复。检查请求数和模型数量，不只检查字段存在。
- 在 `migration.rs` 现有测试模块覆盖：v21 完整明细回填、不完整明细整组不回填、旧模型身份不可确认、不同设备隔离、空库升级和重复迁移。保留旧金额与旧请求总数不变的断言。
- 扩展 `src/__tests__/periodRange.test.ts`，覆盖日期边界、同端点同模型跨日累计、不同端点不混合、未记录差额，以及 `__proto__` 等模型名不会改变累加结果。
- 清空/过期清理 `request_logs` 后，模型统计保持不变；调用 `delete_row` 或 `delete_by_date` 后，模型计数随对应 `daily_stats` 行一并删除。统计删除不会重新扫描仍存在的旧请求日志恢复计数。
- WebDAV 的 `create_backup_copy` 仍删除整张 `daily_stats` 的内容，新字段随之排除；`merge_from_backup` 继续不导入统计。配置导入导出、已有明细上传规则保持原样，不把此次功能扩成统计同步。
- 使用隔离原生应用及受控上游产生真实请求，打开「统计」展开端点；检查两个模型的数量、别名合并、父子合计、四周期及自定义日期、实时刷新、键盘操作和长名称。清理明细、重启应用后再次确认计数保留；恢复隔离数据，不动正式数据库。
- 实施时运行受影响的 Rust 测试、`pnpm test src/__tests__/periodRange.test.ts` 和 `pnpm check:front`，并以原生界面作为交互验收。通过后更新本计划进度、`progress.csv` 和 `CHANGELOG.md`，按统计模块提交。
